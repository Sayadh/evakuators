# 16. Նախապատվերներ (Pre-orders, 2026-11-17)

Գների հավաքում՝ նախքան պատվեր լինելը։ Օպերատորը նկարագրում է աշխատանքը
(որտեղից/ուր, մեքենա, քաշ, վիճակ, ռոլիկներ, մեկնաբանություն)՝ **առանց
հաճախորդի կոնտակտի**, **բոլոր ակտիվ վարորդները** տեսնում են այն և ստանում
push, ով հարմար է համարում՝ գրում է իր գինը, օպերատորը ընտրում է։

Ոչ մի DispatchOrder, առաջարկ, միջնորդավճար կամ նշանակում — նախապատվերը
ոչ ոքի ոչնչի չի պարտավորեցնում։

## Կանոններ

| Հարց | Որոշում |
| --- | --- |
| Ով է ստանում | **Բոլոր** `ACTIVE` վարորդները (2026-11-18)՝ առանց մեքենայի ֆիլտրի։ Վարորդն ինքն է որոշում՝ հարմար է, թե ոչ։ Ստացողների ցանկ չկա. ստեղծելուց հետո հաստատված վարորդն էլ է տեսնում բաց նախապատվերները |
| Կրկին ծանուցել | Ադմինի կոճակ՝ նոր push-ի փուլ բոլոր ակտիվ վարորդներին («խնդրում ենք նայել»), միայն բաց նախապատվերի համար (`POST …/notify`) |
| Ինչ է տեսնում վարորդը | Աշխատանքը, իր հեռավորությունը (ուղիղ գիծ), իր գինը։ **Երբեք** հաճախորդին, ներքին նշումը, ուրիշների գները |
| Ուր | **Պարտադիր** է՝ նկարագրությունը (≥ 2 նիշ), կոորդինատները՝ ըստ ցանկության |
| Գին | 100–10 000 000 ֏, փոխվում/հետ է կանչվում, քանի դեռ բաց է |
| Բաց է | `status = OPEN`։ Ժամկետ (deadline) **չկա** |
| Փակում | **Միայն** օպերատորը (`close`)։ Պատվեր տալը չի փակում |
| Վարորդի ցուցակ | **Բոլոր** բաց նախապատվերները (նաև 100+) + վերջին 2 օրում իր գնահատած փակվածները |
| Ամսական մաքրում | Worker-ը ամեն ժամ ջնջում է **նախորդ ամիսներին փակված** նախապատվերները՝ գներով և կապերով (`purgePastMonths`, Երևանի ժամով)։ Բացերը մնում են՝ ինչքան էլ հին լինեն։ Ստեղծված պատվերները մնում են |
| `LIVE_DISPATCH_ENABLED=false` | Ստեղծելը, «Կրկին ծանուցել»-ը և «Պատվեր տալ»-ը մերժվում են `FEATURE_DISABLED`-ով (worker-ը անգործ է, push-երը կմնային հերթում)։ Ադմինի էջը զգուշացնում է և անջատում կոճակները։ Վարորդը բաց նախապատվերին գին գրել կարող է |

## Փոխարկում պատվերի (`POST /ops/dispatch/pre-orders/:id/convert`)

1. Ստեղծվում է **FIXED** պատվեր՝ ընտրված վարորդի գնով, նախապատվերի բոլոր
   տվյալներով և հաճախորդի հեռախոսով (պահված կամ փոխարկելիս գրված)։
2. Կապը գրանցվում է `PreOrderConversion`-ում (`orderId`, `driverId`, գին)։
   Նախապատվերը **մնում է բաց**․ եթե վարորդը մերժի, «Պատվեր տալ» հաջորդին
   ստեղծում է երկրորդ պատվեր։ Մանրամասն էջը ցույց է տալիս բոլոր ստեղծված
   պատվերները և առաջարկի ելքը (ընդունված/մերժված/ժամկետանց)։
3. Վարորդին ուղարկվում է սովորական manual offer։ Եթե այն մերժվում է
   (offline, ուրիշ պատվերի վրա), պատվերը **մնում է** — պատասխանը
   `offered: false, offerError`, օպերատորն ուղարկում է պատվերի էջից։

Երկու քայլն էլ idempotent են նույն բանալիով (offer-ի բանալին՝ `<key>-offer`)։
